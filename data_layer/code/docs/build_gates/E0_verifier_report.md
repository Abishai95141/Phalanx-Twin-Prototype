## 7. W1 readiness

My throwaway module (`runs/e0/w1demo.py`) was written from the READMEs only:
- a first-order lag in SI rad/s with a keyed disturbance;
- a sensor on its own clock domain (60 Hz, +50 ppm) with keyed noise;
- dictionary ParamSets (`n2_100pct` comes back as 1760.339 rad/s);
- CIR → fast path → two-tree store → replay → leak audit.

It worked first time: 300 samples, 300 replayed, 0 leaks, bitwise identical over two runs. Block mode equals step mode, and snapshot at 1111 → restore → continue equals the uninterrupted run.

Friction found:
1. **Shared dictionary edits.** Every W1 WP must add constants or tables in one shared `tables/constants.yaml`. Each addition requires a `dict_version` bump, a `releases.yaml` entry and `make contract-docs` (the `dictionary.<ver>.json` file name changes); otherwise `test_current_version_is_released_with_this_hash` and the docs-drift test fail (probe confirmed). Eight parallel WPs will conflict. W1 ownership of `configs/tejas/dictionary/**` and `docs/contract/` is also unassigned.
2. **No SI→EU helper.** There is no per-channel SI→EU conversion API (scale and offset, %-of-rated); M13 has to hand-roll it.
3. **No sampled-output → CIR helper.** There is no helper to turn a clock-domain sensor's padded outputs into CIR rows. The toy pads with NaN and does not output sample indices, and the `t_true` semantics for interpolated samples are undocumented.
4. **Fast path doesn't check the dictionary.** It accepts a nonexistent lane ("Z"), the wrong LRU (DFCC for ENG.N2) and a value of 1e6 %; only an unknown `param_id` is rejected (probe `runs/e0/probe_fastpath.py`).
5. **Unit-string mismatch.** The dictionary uses `lb/hr`; `BatteryConfig` uses `lb/h` and compares strings exactly. This is already in the carry-forward.
6. **No worked example of the AD-22 kernel layout** (flat float64/int64 vectors with name→index constants) inside `ModuleBase`/`StateSchema`.
7. **Usage-mode time advance is slow by default.** An event-only system takes ~73 s per tail-year at the default `block_len` 1024, versus ~2 s at `block_len` 864,000. There is no "jump to next event" mode.
8. **Stale line in `ground/README.md`:** "plain maps until … W0.X".

## 8. Discrepancies

- **R-LSB-BNR text vs code.** The rule statement (`rules.yaml`, A-W0.3-19) gives LSB = 2^ceil(log2(max|range|/(2^(n−1)−1))). The code uses 2^(n−1) counts on the negative side and an unsigned 2^n−1 branch. For example, ELEC.BATT.VOLT gets 2⁻¹⁰, while the rule formula gives 2⁻⁹.
- **AD-22 vs AD-36/37 and core.** AD-22 says "snapshots store key path, block index and offset", but core snapshots store the RNG identity, with draw indices in module state. The W0.6 carry-forward says "rate-group phase lives in the int state", but core manages the phase in `RateGroup`.
- **Arrow schemas not published.** `docs/contract/README.md` claims `contract/v0/` holds Arrow schemas; only Avro, JSON-Schema (3 topics) and Markdown are there.
- **Minor:**
  - RULES.md says AD-01…AD-35, but the register runs to AD-40.
  - The §12 topic table omits `orders.commands` (AD-38 adds it).
  - The W0.4 tracker row has no merge hash.
- Tracker, audit-log test counts and AD-35…AD-40 are otherwise consistent with the code (person strings, key vocabulary, the `record_id` tuple).
