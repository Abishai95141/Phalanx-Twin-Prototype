## Deliverables

### M18: maintenance world (discrete-event, `on_event`)
- **Work orders (snags)** come from:
  - pilot write-ups;
  - BIT/HMS codes;
  - inspections;
  - exceedances;
  - orders.
- **Troubleshooting** with misdiagnosis (NFF/RTOK).
- **Parts demands** (AOG/MCM/PHU) with CAG-calibrated delay distributions; cannibalisation.
- **Inspections** with detection probabilities.
- **Other activities:**
  - servicing;
  - modifications and software loads;
  - life-limited part retirement;
  - depot turnaround.
- **Availability** is computed from job states, SCIR-style in 15-min bins, and never asserted.
- **Records:** the §10 types, with IAF-relabelled synthetic codes (AD-19). Emitted as `maint.records` in contract v0.
- **Data-quality defects** are injected **after** truth, with a defect manifest:
  - CANN under-reporting;
  - missing part records;
  - wrong form;
  - reconciliation lag;
  - free-text noise;
  - "XXX" S/N;
  - duplicate snags.
- **Event chains** 1–8 (§10), including the Tejas JFS cold start, brake software and the gauging artefact.

### M21: orders
- Typed, sim-time-stamped and logged; idempotent `order_id`; the §11.1 vocabulary.
- **Validation:** authority and airworthiness (no release with open grounding defects); resources and supply.
- **Lifecycle** on `orders.status`.
- **Execution is imperfect:** partial wash recovery, detection probability, misdiagnosis, induced defects.
- **Information discipline:**
  - the observation set is `ObservationView.as_of(t_decision)`;
  - orders citing un-ingested evidence are rejected (`ingested()`, which you index for speed);
  - live orders apply at the next epoch.
- **Event sourcing:** run = f(seed, config, dictionary, order log).
- **Reference policies** in `configs/policies/`:
  - IAF-style hard-time / reactive status quo;
  - scheduled;
  - simple condition-based thresholds.

### M22: snapshot and fork
- Content-hashed snapshots at decision epochs (sortie boundaries), using `core.snapshot`.
- **Copy-on-write branches:** parent snapshot + divergent order suffix.
- **CRN:** exogenous randomness keyed by identity. A newly fitted part draws from its own serial's stream.
- **Fork modes:**
  - **oracle:** true state, privileged;
  - **belief:** hidden states resampled consistent with observations via a pluggable posterior interface; a simple reference implementation;
  - **ensemble:** different exogenous seeds.
- **What-if API:** `snapshot(t)` → `fork(snapshot, branch_id, order_suffix | policy)` → `run(horizon)` → KPIs, with CRN-paired differences and CIs. The KPIs are:
  - MC/FMC availability;
  - flying-task achievement;
  - AOG days;
  - CANN rate;
  - man-hours;
  - cost proxy;
  - in-flight failures.
- **Forks run in usage mode by default.** In W1, use a usage-mode fleet driven by W1-local fixtures; real M02/M10 come in W2.6.

## Acceptance

| ID | Criterion |
|---|---|
| A1 | Key integrity across all records; SCIR availability arithmetic; resource and authority rules (negative tests) |
| A2 | Availability priors (Su-30 / CAG) reproducible in calibration: an `xfail(strict=True, "W2.6")` if they need real usage input; defect rates match targets |
| A3 | **Status-quo policy reproduces the open-loop KPIs** (no orders vs status-quo orders) |
| A4 | Orders: schema validation; **no look-ahead** (property test: any order citing a record with `t_ingest > t_decision` is rejected); idempotent `order_id`; replay of an order log reproduces the live run bitwise |
| A5 | Fork: snapshot → restore → continue bitwise; identical suffixes give identical branches; CRN audit; **paired-difference variance below independent-seed variance** (n stated) |
| A6 | Contract conformance for `maint.records`, `orders.commands` and `orders.status`; the defect manifest is restricted |
| A7 | Deterministic; snapshot round-trip of queues, inventories, in-transit spares and pending events |
