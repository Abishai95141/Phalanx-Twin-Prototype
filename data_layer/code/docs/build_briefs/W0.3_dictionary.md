## Deliverables

### 1. YAML source schema, one file per subsystem
Engine, FADEC, FCS/air data, hydraulics, fuel, electrical, ECS, gear/brakes, avionics/status, time, etc.

**Content per channel** (architecture M01):
- `param_id`, name, units (pint-parseable), physical quantity;
- source LRU, lane and channel;
- sensor type;
- native step, recorder LSB, ADC bits, range;
- bus mapping (1553 RT/SA/word, or ARINC-429 label/SDI), encoding, validity mapping;
- rate groups (acquisition / bus / record);
- sinks (cockpit, CDR, ECMS/HUMS, MPDRU, FTI);
- calibration polynomial and date, limits;
- evidence tag (`DIRECT`, `DIRECT-unnamed`, `TRANSFER: <donor>`, `MEASURED`, `ASSUMPTION`) and source;
- `PROXY` flag.

**Also:** code tables (validity enums, BIT code formats as **synthetic** `SSS-NNN`), LRU list, rate-group table, sink table.

**Synthetic labelling:** the bus mapping is the **synthetic Phalanx ICD**. It is labelled synthetic in every
generated artefact and never claimed to be the real Tejas ICD (RULES.md rule 6).

### 2. Seeder: `parameter_inventory.csv` → YAML sources
- All 189 logical rows.
- Expands redundancy (lanes) to physical channels: about 300 per the architecture. Verify, and report the actual count.
- Carries the evidence tags and sources over.
- Where the CSV lacks a value the schema needs (e.g. a recorder LSB, a bus word), fill it per the report/notes, or mark it `ASSUMPTION` with a sweep range and an `assumptions.md` row. Group these rather than writing 300 rows: one row per *rule* that fills a class of values, listing the affected params.

### 3. Compiler: YAML → `dictionary.<ver>.json`
- Canonical, sorted.
- Content-hashed with blake2b over canonical bytes.
- Semantic version.
- **Validation on compile:**
  - a JSON-Schema or typed validation of every field;
  - units parse and match the declared physical quantity;
  - ranges consistent with ADC bits / LSB;
  - rate groups exist;
  - bus addresses unique, with no RT/SA/word or label/SDI collisions;
  - every channel has a producer LRU and ≥1 sink (**no orphans**);
  - every value has a tag + source (**100 %**);
  - `PROXY` items listed.
- Compilation is deterministic: same sources → same bytes → same hash, on repeated runs and in a fresh process.

### 4. Generators
- **TMATS stub:** IRIG 106 Ch9 attributes for the recorder setup (G, R, M, P groups as needed for PCM/1553/analog channel definitions). Labelled synthetic. **Must parse with pyChapter10** (installed as `chapter10`), or, if pyChapter10 has no TMATS parser API, with a documented parser plus a round-trip test. Report which.
- **Synthetic ICD stub:** human-readable (CSV/Markdown) bus map generated from the dictionary.
- **Docs:** a generated parameter table under `docs/contract/` is acceptable. Coordinate the path in your report rather than writing outside your owned paths; you may generate into `build/` or `src/phalanx/dictionary/generated/` and propose the final location.
- **Public API for consumers:** `load_dictionary(version|path) -> Dictionary` with lookups by `param_id`, by LRU, by bus address and by rate group; `dict_version` and `dict_hash` accessors.
  - W0.4 (contract) and W1 modules consume this.
  - The Arrow **contract** schemas are generated by `dictionary/contract/` (W0.4). After both merge, the coordinator wires the compiler to invoke it. Expose a hook (a plugin list or a function call) where the compiler can run extra generators, and document it.

## Acceptance (map each to named tests)

| ID | Criterion |
|---|---|
| A1 | 100 % of channels carry an evidence tag and a source; a negative test shows a missing tag fails compilation |
| A2 | Hash stable across two compiles and a fresh-subprocess compile; any source edit changes the hash |
| A3 | No orphan channels; no bus-address collisions; negative tests for each |
| A4 | Units parse (pint) and match the physical quantity; range vs ADC/LSB consistency; negative tests |
| A5 | TMATS stub parses (pyChapter10 or a documented parser) and round-trips the channel list |
| A6 | Seeder covers all 189 inventory rows; the physical channel count is reported and tested |
| A7 | Every `ASSUMPTION`/`PROXY` value appears in `docs/assumptions.md` (per-rule rows) and has the PROXY flag in the dictionary |
| A8 | `make check` green |

## Notes

- Native steps measured on DASHlink: N1/N2 0.04 %, EGT 0.8 °C, FF 8 lb/h lattice. These are **proxy-mode (DASHlink) values**, not Tejas. Keep the Tejas dictionary (`configs/tejas/dictionary/`) separate from any proxy dictionary. Proxy-mode dictionaries are built in W2.4; just make the schema support multiple platform configs.
- Restricted values: check report Appendix A before using any limit. Never use `research_sources/_restricted_do_not_cite/`.
