## Deliverables

Each subsystem is a lumped network or state machine. **N2 is the master variable.** Each one is a separately
testable kernel; together they form one module (or a small set of modules) publishing the `util.*` ports.

| Subsystem | Content |
|---|---|
| AMAGB/PTO | Fixed ratios to N2; `util.pto_power` load back on the engine |
| Hydraulics | Two 280 bar networks:<br>• compensated pump flow limit Q_max(N2);<br>• leakage conductances (from `health.utility`);<br>• accumulators;<br>• fluid temperature;<br>• filter ΔP rising with loading.<br>Outputs `util.hyd_p`, `util.hyd_dp_avail`. Consumes `fcs.hyd_flow_demand` and `env.w_hyd`. |
| Fuel | Tank network: transfer, feed, burn from `eng.wf`.<br>Gauging model: attitude, acceleration and slosh; Class I accuracy.<br>**The false low-fuel artefact at >40° pitch, max AB and <1,200 kg.**<br>Fuel acts as a heat sink.<br>Outputs `util.fuel_mass`, plus `util.mass/cg/inertia` for M06. |
| Electrical | Average-value network with MIL-STD-704F bands. Generator underspeed → 5 kW DC backup / battery, with ≤50 ms transfer. |
| ECS | ε-NTU model. Bleed 2.8 → 6.4 bar and 175 → 440 °C over 75 → 97 % rpm (from `eng.bleed_*`). Outputs `util.bleed_extract`. |
| GTSU-110 JFS start | Battery SOC, OAT and altitude drive start success, with the 3-consecutive-start requirement. Includes the Tejas cold-start failure behaviour. |
| Brakes, tyres, chute | Brakes: energy → heat sink → wear, carbon 3R/4S. Tyres: wear per landing. Chute: streaming limits and life. |
| Fire | Detection state machine (discretes). |

**Health inputs:** `health.utility` (index map from M10; agree it via the interface report).

**Wear and monitoring curves (§9.2):**
- case-drain ΔT flat for ≈5 months, then reaching the limit at ≈11.5 months;
- filter ΔP rise in ≈4 weeks;
- carbon brakes 1,400 landings;
- tyres 4–12 landings;
- HX fouling 3–9 months.

These are parameters; the processes themselves live in M10.
