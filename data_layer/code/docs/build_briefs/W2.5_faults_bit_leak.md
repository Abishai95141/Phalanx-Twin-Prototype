# W2.5: Faults, BIT and the label-leak audit (scope per AD-55)

**Goal.** Fault and degradation data that behaves like a real fleet's:
- faults enter **only through the physics** (AD-18, AD-26, AD-27);
- their signatures match released literature in direction, ordering, magnitude and timing (**B7**);
- BIT and monitoring behave in the right regimes, at the right rates and with realistic false alarms (**B8**);
- fault labels cannot be predicted from anything but the physics. The label-leak audit and G0 are binding guards.

**Scope (AD-55):** B7/B8 **in depth for a priority set of about 10 maintenance-relevant faults**. Every other
catalogue fault is marked "unvalidated" in the catalogue, with a reason. The **label-leak audit and G0 cover all
faults.**

## Deliverables

1. **Priority fault set** (≈10). Choose with evidence, and record the list and the reasons in the README. It should
   span:
   - **engine performance:** compressor fouling, turbine erosion, a Muir-matrix row with released signatures
     (C26);
   - **oil and bearing**, including a **healthy-wear oil-debris process** in M10 (the W2.1c finding: C25
     measured 0.0 µg/h against Bennett's 0.47 µg/h);
   - **sensor drift or bias** (bias is separate from deterioration, AD-26);
   - **hydraulics:** pump degradation or leak;
   - **electrical:** generator or TRU;
   - **brakes and tyres** (W2.1c wear accrual);
   - optionally fuel or ECS.

   For each fault: the physical injection path, the hidden-state truth, the label, and its onset and progression
   laws, with evidence tags.
2. **B7 fault behaviour.** For each priority fault, compare the signature's sign, ordering, magnitude and cascade
   timing against the literature: Muir/NRC matrices (AD-53 convention), accident-board cascades, and the graph
   latencies.
   - Run telemetry mode on the subsystem loops you own or can drive. Start with the engine and FADEC through
     `health.engine` and M12/M13; engine `fault_inject` comes after W2.1b merges.
   - Report a PASS/FAIL table, with n and CIs.
3. **B8 event behaviour.** BIT immature vs mature regimes; false-alarm and CND/NFF rates within literature ranges;
   event-chain timing (the architecture §10 chains); exceedance → conditional inspection. Measure at fleet scale
   in usage mode, at the minimal n for the stated CI.
4. **Power-up BIT** (W2.1c proposal 4). M14 runs PBIT at engine start or power-up instead of at take-off (retires
   PROXY A-W2.1c-4).
   - Define the catalogued power-up event: M02 → M05/M14.
   - Implement the M14 side.
   - **The M02 emission goes through the coordinator to W2.1a.** Until then, keep a tracked exception.
5. **Preflight aborts** (W2.1c proposal 6). M11 consumes `ops.launch`, so preflight fault modes can abort before
   take-off (A-W2.1c-6).
6. **Label-leak audit** (binding; replaces the STUB). A texture-only classifier and a metadata-only classifier
   cannot predict fault labels: chance-level within pre-stated bounds, with negative controls (a planted leak is
   caught).
   - Run it on **all** catalogue faults.
   - Also run **G0**: pipeline-only metadata at chance.
   - Fault and healthy data must come from the identical generation path.
7. **Catalogue hygiene.** The priority faults are marked validated, with evidence. Every other fault is marked
   "unvalidated (AD-55)".
