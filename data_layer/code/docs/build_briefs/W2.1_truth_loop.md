# W2.1: Truth-loop integration (M02–M11 in the 240 Hz kernel)

**Goal.** Wire every merged truth-layer module into one deterministic closed-loop system:
- FCS ↔ airframe;
- FADEC ↔ engine;
- utilities driven by N2;
- environment, pilot and scenario driving the aircraft;
- health and faults perturbing the physics.

Wire it exactly as the frozen catalogues say. This WP turns nine separately tested modules into one aircraft. **Cohesion is the deliverable.**

**Owned paths:**
- `src/phalanx/integration/` (new): system builder, fused truth-loop kernel, runtime validators, sortie runner;
- `tests/*/test_integration_*.py`;
- the W2.1 section of `docs/assumptions.md`.

Changes to other packages are limited to the interface items listed below. Each needs a focused commit naming the AD it implements. Report every edit outside `src/phalanx/integration/`.

## Deliverables

### 1. System builder (`integration/system.py`)
- Build the `phalanx.core` `System` **from the published `ports.py` bindings**. Never hand-wire. A binding with no producer is an error.
- Fixed Gauss–Seidel order (architecture §8): environment → guidance/pilot → FCS → engine/FADEC → airframe → utilities → sensors → lanes.
- Every back-edge is a documented one-frame delay:
  - `af.alt`/`hag`/`tas` → env;
  - `af.*` and `eng.n2` → pilot;
  - `af.alpha`/`beta`/`qbar` → FCS;
  - `fcs.surf_pos` → M12 → M13 position lanes;
  - lanes → FADEC/DFCC.
- Identity: per tail, serials and per-tail config go **into the config hash** (AD-48.8).
- Stream registry includes every module's `STREAMS`, including `bus.clocks`, `recorder.writer` and `acquisition.core`.

### 2. Fused truth-loop kernel (`integration/fused.py`)
- The FCS ↔ airframe ↔ engine ↔ FADEC segment as one `@njit(cache=False)` `step_block` that calls the modules' kernels.
- It must equal the per-step scheduler path **bitwise** (AD-36).
- Numba pitfalls apply: no fused sin/cos in reference paths; explicit products instead of `**2`; `cache=False` for fused callers.

### 3. Runtime event-protocol validator (`integration/validate.py`)
- Wrap the event queue so that **every dispatched cross-module event** is checked against `w1_events.yaml`: kind, producer, consumer, payload keys present.
- This is required because declaration checks alone missed real emitted payloads (M18 MOD without `pos`).
- On in all tests; off in production for speed.

## Entry gates from the W1.3b re-review (must be closed early in W2.1)

1. **Flame-out detection at altitude.**
   - Problem: on M07 at 20–30 kft, an idle flame-out is never detected. The real spool runs down more slowly than the fixture's, so the −3 %/s N2-rate threshold and the "corrected N2 > demand − 5 %" gate never overlap.
   - Fix: schedule `fo_n2dot` and the gate on altitude/δ, or latch the deceleration over a window. Also confirm relight on N2/PS3 recovery, not T5 only.
   - Pair with the M07 low-power T5 calibration (W2.3): SLS idle T5 is 277 °C vs ≈409 °C released, so the T5 lane sits on the 371 °C harness floor at part power.
2. **FADEC schedules harmonised with M07.**
   - Problem: the N1 limit is reached at about PLA 75 at SLS, and the FF correlation sign inverts there.
   - Constraint: the M07 governor-gain window is about 1 < Kp < 3 (idle limit cycle below, sign loss above). Keep W2.4a identification inside it.
3. **T1 below its span** (−54 °C span floor vs a −56.5 °C stratosphere).
   - Problem: on-board-model substitution of T1 gives N1c 1.065 above the cap.
   - Fix: hold T1 at the span floor, or use air-data T1 (P0/T1 from air data). Widening the span is a dictionary 0.1.3 question.

## Entry gate 4 (from E1-MF): M08 limiter hand-off

The deterministic property grid (192 points) violates the M08 limiter bounds at **29 points** on the base M08:
- PS3 transient up to 1.058;
- N1 transient up to 1.0225;
- PS3 "steady" up to 1.0095.

**Mechanism.** The N1 isochronous limiter takes over during the acceleration, and PS3 crosses its maximum while N1
is in control. Past its limit, the PS3-max integrator follows the falling selected command through the 1 s
integrator-feedback lag (the `_ifb` equilibrium clamp is safe-side only), so the PS3 limiter never takes over.

**Fixes E1-MF measured and rejected:**
- A two-sided clamp breaks two W1.3b T5 tests and creates a T5↔PS3 limit cycle.
- A two-sided clamp except T5 under-damps the dense corner and adds four steady violations.

**Requirements:**
- Retune the limiter hand-off and integrator management **on the real M07**: anti-windup and bumpless transfer
  between the MIN/MAX branches, per the C-MAPSS40k structure, keeping the governor inside the Kp window.
- The four pinned `@example(...).xfail(raises=...)` cases in `tests/property/test_fadec_limiter_property.py` turn
  green, and the full grid passes without widening any bound.
- The W1.3b A1–A7 tests stay green.
