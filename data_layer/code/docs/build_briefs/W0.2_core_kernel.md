## Deliverables

### 1. `core/time.py`: AD-35 time base
- int64 ns.
- `truth_step_time_ns(k)` = `(k*10**9)//240`, exact for large k (Python int or overflow-checked int64).
- `TRUTH_HZ = 240`.
- Rate groups that are integer divisors of 240 Hz.
- **Oscillator / clock-domain schedule:** for a domain with nominal frequency f, offset Δ (ppm, per unit) and phase φ:
  - sample instants computed exactly in integer or rational arithmetic and floored to ns;
  - no float accumulation;
  - must stay exact over ≥ 10 h of sim time at f up to 1 kHz.
  - Provide "the latest truth step at or before t" and the interpolation weights. LRU domains interpolate truth at their own tick (architecture §6 M13 and §8).

### 2. `core/rng.py`: identity-keyed counter-based streams (AD-15)
- `KeyPath`: an ordered tuple of typed identity components (scenario, tail, serial, sortie, subsystem, sensor, component, …).
- Root seed: 128-bit.
- Component → integer mapping: a stable, documented, version-pinned digest (e.g. blake2b of the canonical UTF-8 encoding → uint32 words) feeding `SeedSequence(entropy=root, spawn_key=…)` → Philox (or a counter-based equivalent).
- **Never seed arithmetic.**
- API:
  - `stream(key_path)` → Generator;
  - counter-addressable block draws (`block(key_path, block_index, size)`, independent of what was drawn before) so modules can draw per-step or per-block without order dependence;
  - stream state is serialisable (counter position).
- **Stream registry:** a namespace of declared subsystems/components. Undeclared names are an error, which prevents typo-forks.
- **Test that adding a new stream or consumer never perturbs an existing stream (CRN, I8).**
- The mapping is part of the reproducibility contract: write a golden test that pins the first draws for a fixed key path.

### 3. `core/module.py`: the §5.5 module contract
- `Port(name, unit, dtype, shape, rate_group)`.
- `ParamSet`: frozen, hashed, values with provenance tags.
- `Module` protocol: `init(params, keys)`, `step(state, inputs, t, dt)`, `on_event(state, event, t)`, `get_state` / `set_state`, `id`, `version`.
- **State representation:**
  - a flat, explicitly typed pytree of numpy arrays and scalars, so it works for Numba (arrays) and JAX (pytrees). AD-22 isn't decided yet (W0.6 benchmarks it in parallel), so stay backend-neutral;
  - canonical, versioned serialisation to bytes: header (sorted keys, dtype, shape, schema version) + little-endian raw buffers;
  - **no pickle**, and no zip timestamps (`np.savez` bytes aren't stable);
  - content hash (blake2b).
- Unit checking at port boundaries with pint, in validation mode only (zero cost otherwise).

### 4. `core/scheduler.py`: the 240 Hz kernel
- Fixed-step truth loop.
- Integer rate groups with sub-stepping (a module may sub-step internally).
- Fixed Gauss–Seidel module order with **documented one-frame delays** for loops (§8).
- **Block execution interface:** `run(n_steps)` calls `step_block` when a module (or a fused group) provides one, else falls back to per-step `step`. Both paths must give bitwise-identical results; test this.
- Reference per-step interpreter for clarity and tests.
- Input/output wiring by port name, with type, unit and shape checks at build time.

### 5. `core/events.py`: simulation-time event queue for discrete modules
- Deterministic ordering key: (t_ns, priority, insertion sequence).
- Serialisable for snapshots.
- Events are never ordered by wall clock or object identity.

### 6. `core/snapshot.py`: world snapshot I/O
- Aggregates all module states + RNG stream counters + event queue + config/dictionary hashes + order-log hash.
- Content-hashed and versioned.
- `restore(snapshot)` → world.
- Copy-on-write fork is M22's job later; provide the primitives: snapshot bytes are self-describing and restorable.

### 7. `core/manifest.py`: run manifest (§15)
- git commit (passed in, or read via `git rev-parse`; never wall clock);
- config hash, dictionary hash, library versions, backend, BitGenerator, stream table, order-log hash.
- Deterministic JSON (sorted keys).

### 8. Toy system for tests
`tests/` only, or `src/phalanx/core/toy.py` if useful as a reference example. Two modules:
- **(a)** a spring–damper truth module driven by a keyed process disturbance;
- **(b)** a noisy sensor sampling it on its own drifting clock domain with interpolation, plus keyed measurement noise.

It is a test fixture for the kernel, not a physics deliverable. Label it as such in its docstring.

## Acceptance (map each to named tests)

| ID | Criterion |
|---|---|
| A1 (I1) | Same (seed, config) → bitwise-identical outputs: run twice in-process and in a fresh subprocess, compare hashes |
| A2 (I2) | `get_state` ∘ `set_state` round-trips exactly, for every toy module and the event queue; property tests over random states |
| A3 | Snapshot at step k → restore → continue to N is bitwise identical to an uninterrupted run to N, for several k incl. 0 and N |
| A4 (I8) | Two forks from one snapshot with identical suffixes are bitwise identical. Two forks with different "orders" (here: a changed parameter on one module from step k) share identical exogenous draws on every unaffected stream (CRN audit) |
| A5 | Adding a new stream or consumer leaves every existing stream's draws unchanged |
| A6 | Block execution == per-step execution, bitwise |
| A7 | Time base exact: `truth_step_time_ns` matches exact rational arithmetic for k up to 240·3600·100; oscillator schedules exact over 10 h; property tests |
| A8 (I3) | A unit mismatch at a port boundary is caught in validation mode; no cost in production mode |
| A9 | Event-queue ordering is deterministic under ties; the snapshot round-trip preserves pending events |
| A10 | `make check` green; static audit clean |
| A11 | Golden RNG test pins the first draws for a fixed key path, so any change to the mapping is caught |
