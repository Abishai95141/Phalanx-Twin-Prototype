## Deliverables

### M10: health
- **Hidden-state catalogue:** the 50 states, plus per-serial life consumption, keyed by tail / engine serial / component serial (§5.3).
- **Process family per mechanism** (§9.2 table):
  - Wiener fouling with wash reset;
  - gamma erosion with fighter severity S = 1.5–2, swept;
  - rub-in;
  - abnormal onset (N-CMAPSS form);
  - Weibull + Paris cracks;
  - Poisson shocks;
  - latent maintenance-induced defects;
  - two-state Markov intermittents;
  - utility wear curves;
  - Tejas-specific discrete events.
- **Usage drivers** are inputs (cycles, time at temperature, g, landings, starts, dust and salt) from M02/M06/M07/M09.
- **Outputs:** `health.engine`, `health.utility`, `health.sensor_bias`, `health.actuator` (`W1_interfaces.md`), plus restricted `labels.truth` records.
- **Sensor bias and component deterioration are separate latent processes with separate truth (AD-26).**
- **Both tiers:** usage mode advances health per sortie; telemetry mode holds health and accepts M11 events.

### M11: faults
- Scheduler, stochastic or scripted, that applies faults as **state perturbations** through events (`on_event` of the target module). Faults never take a different generation path (I6).
- **Typed dependency graph as data:** edge types shaft, hydraulic, thermal, data/electrical, discrete, mechanical; each edge has a transfer function and a latency. It also serves normal coupling and validation invariants (AD-27).
- **Sensor-fault modes:** bias step, drift, stuck, intermittent, spikes, open/short, slow response (applied in M12 via events).

### M14: monitoring and BIT (event-driven over CIR and lane states)
- CBIT/PBIT/IBIT/MBIT with persistence and latch logic. Every caution has:
  - a missed-detection probability and a false-alarm rate;
  - a CND/NFF propensity;
  - sympathetic cascades;
  - code bursts after software updates.
- CWS: 30 legends, 4 voice warnings.
- ECMS/HUMS:
  - gas path at 10 Hz, slow channels at 1 Hz;
  - event snapshots, 5 s pre + 25–35 s post;
  - take-off record 6–10 s;
  - **8 LUIs updated twice per flight**;
  - TAC cross-check.
- Exceedances; PFL/MFL split.
- **Two calibrated regimes:**
  - immature: 0.1–1 FH between false alarms;
  - mature: ≥50 FH, and ≤1 per 1,000 flights for gas-path EHM.
- BIT runs on the **same coloured, heavy-tailed sensor model** as the recorded data (I6).
- **Emits** `events.bit_faults`, `events.exceedances`, `events.cautions` and `usage.counters` in the contract v0 schemas (`load_contract("v0")`; validate every batch).
- **Label-leak audit hook:** provide `leak_features` for `phalanx.validation.guards.label_leak_audit`. It is currently a STUB there; you implement the feature extraction in your package and W2.5 wires it.

| A3 | **Bias and deterioration remain separate truths:** perturbing one never changes the other's truth trajectory (I-test, property) |

| A6 | Contract conformance: every emitted event or counter batch validates against contract v0; restricted labels never reach consumer topics |
| A7 | Deterministic, CRN across forks for exogenous fault draws; snapshot round-trip including latches and persistence counters |
