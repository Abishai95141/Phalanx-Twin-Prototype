## Deliverables

### 1. `validation/battery/`: clean library ports of B1–B6
- Same estimators as round 2 (pre-registration + `battery.py` + `corr_check.py`). **Port, don't re-invent:**
  - same band definitions, filters and window rules;
  - same distance definitions;
  - same real-vs-real bars (D_tail, D_temp);
  - same bootstrap fail rule (one-sided 95 % lower bound of D_sim − D_tail > 0).
- Inputs: a typed, documented flight-data structure, e.g. a per-flight dict of channel arrays at the analysis rate + phase labels + metadata. Make it something the build's proxy-mode outputs (W2.4) and the contract reader can feed later.
- Each test returns a structured result: distance(s), bars, n flights, verdict, bootstrap CI.

### 2. `validation/guards/`
- G0 trivial-cue audit (pipeline-only metadata at chance).

Port the existing implementations where they exist.

### 3. `validation/samples.py`: deterministic sample selector
- Fixed seed via `phalanx.core.rng` if it exists by the time you need it; otherwise a local SeedSequence with a fixed spawn key, documented. **No global RNG.**
- Saves flight lists.
- Records n and the justification in the result file (RULES.md rule 1).

### 4. `validation/credibility.py`
A NASA-STD-7009B credibility-card **stub**:

- domain of validation;
- Level-2 ceiling against proxy data, stated.
