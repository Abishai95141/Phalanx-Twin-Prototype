# Ground-decoder contract (architecture §12) — W0.4

The contract is the one stable boundary between the Phalanx data layer and downstream predictive-maintenance
and availability solutions. It is identical on the fast path (CIR → contract, `provenance = direct`), the full
path (CIR → bus → Ch10 → ground decoder, `provenance = full_path`, W1.7) and for future real data (AD-12).

It lives under the M01 dictionary package so that it is "generated by M01" (AD-14). After W0.3 merges, the
coordinator wires the dictionary compiler to call this generator (W0.X).

## Layout

| Path | Content |
|---|---|
| `spec/v0/contract.yaml` | The **current** minor version of the v0 line (0.2.0, W2.2, frozen AD-56): version, time scales, record_id rules, enums, flag sets, shared field sets, assumptions |
| `spec/v0/topics/*.yaml` | One file per topic: fields (type, nullability, units, basis), event/ingest time, partitioning, record_id key, row invariants |
| `spec/v0.1.0/` | **Frozen 0.1.0** (AD-41), kept verbatim; loads with `load_contract("0.1.0")`, hash `18d7627b...` |
| `MIGRATION.md` | Migration notes between versions (0.1.0 → 0.2.0); helpers in `phalanx.ground.migrate` |
| `loader.py` | Strict loader (duplicate YAML keys, unknown keys, missing nullability, dangling refs and unregistered assumptions are errors); canonical form and hash |
| `model.py` | Frozen dataclasses: `Contract`, `TopicSpec`, `FieldSpec`, `EnumDef`, `FlagSet`, ... |
| `arrow.py` | Spec → `pyarrow.Schema` with field metadata; consumer view; schema fingerprint |
| `validate.py` | `validate_table`: every batch crossing the boundary is checked (A7) |
| `jsonschema_gen.py` | JSON-Schema (draft 2020-12) for manifests and orders; Arrow ↔ JSON documents |
| `avro_gen.py` | Avro schemas from the contract (v1.x Kafka), structural checker, inverse mapping |
| `markdown.py`, `generate.py` | Human-readable summary and the generated artefacts under `generated/v0/` |
| `examples.py` | EXAMPLE records per topic (valid, meaningless; docs and interface tests only) |

## Public API

```python
from phalanx.dictionary.contract import load_contract, ContractViolation

c = load_contract("v0")  # the current minor version (0.2.0); load_contract("0.1.0") for the frozen 0.1.0
c.version  # "0.2.0"
c.hash  # blake2b-256 of the canonical spec (the contract identity)
c.schema_hash  # blake2b-256 of the generated Arrow schemas
c.schemas["param.samples"]  # pyarrow.Schema (full view, restricted fields included)
c.consumer_schema("sortie.manifest")  # restricted fields dropped; restricted topics raise PermissionError
c.restricted_part_schema("sortie.manifest")  # restricted fields + join keys (restricted tree only)
c.restricted_fields("sortie.manifest")  # ("root_seed", "rng_stream_table")
c.topics["param.samples"].event_time  # "t_sample"; .ingest_time, .partition_by, .record_id_key, .checks
c.enums["Validity"].names  # ("NORMAL", "NO_COMPUTED_DATA", ...)
c.quality_flags.mask("SENTINEL", "GATED")
c.quality_flags.reserved_mask
c.validate("param.samples", table)  # raises ContractViolation listing every violation
c.json_schema("orders.commands")  # consumer view; audience="full" for producers
c.avro_schema("param.samples")
```

Regenerate the artefacts after a spec edit: `python -I src/phalanx/dictionary/contract/generate.py`
(`--check` exits 1 on drift; a test enforces it).

## Conventions (all decided in the spec; see `generated/v0/contract.md`)

- **Time:** int64 ns everywhere (AD-35). Every time field except `t_record` is on the simulated UTC calendar
  (POSIX ns); `t_record` is the recorder RTC in ns from the recording's own origin (A-W0.4-1).
- **record_id:** blake2b-128 (person `phalanx.rid.v0`) of a typed, length-prefixed encoding of the topic and its
  `record_id_key` (A-W0.4-2). Implementation: `phalanx.ground.rid`.
- **No NaN** in any float field; missing = null; a sentinel is a value plus the SENTINEL flag.
- **Restricted** data (`labels.truth`, manifest seeds) never reach the consumer view (I5). Storage keeps
  them in a physically separate restricted tree (`phalanx.streaming`, R1). Loader rule: a restricted field
  of a consumer-visible topic must be nullable and must not be a key, time or partition field, so the
  consumer record is complete without it.
- **Evidence basis** on every field: `ARCH §n` (mandated by the binding architecture), `TRANSFER: <src>`,
  `ASSUMPTION: A-W0.4-n` (registered in `docs/assumptions.md`).

## Versions

- **0.1.0** frozen by the owner at E0 (AD-41); archived in `spec/v0.1.0/`. `FROZEN_VERSIONS` in
  `tests/unit/test_contract_generation.py` checks every frozen version in every spec directory.
- **0.2.0** (W2.2, additive) frozen by the owner (AD-56); hash `a4396f1d...`: `param.samples` gains `recording_id` and
  `sink` (AD-25 per-sink recordings, AD-45; A-W0.4-22). Migration note: `MIGRATION.md`; the additivity check and
  the 0.2.0 ↔ 0.1.0 projection/upgrade are `phalanx.ground.migrate`
  (`tests/unit/test_w22_contract_020.py`, `tests/integration/test_w22_contract_020_full_path.py`).

## Known limitations

- Golden hashes in `test_contract_generation.py` pin 0.1.0 and the current spec; any change needs a semver bump,
  a migration note and a decision-register entry.
- No Avro library is pinned, so the Avro check is structural plus an inverse mapping; the binary round trip test
  is skipped until `fastavro` is added (requested in the W0.4 report).
- Synthetic code tables (event codes, legends, WUC-like codes) are referenced as strings; their content belongs
  to M01/M14/M18 and is labelled synthetic there.
- The full-path rules for `record_id` (cumulative Ch10 packet counter, message index) are specified here but
  implemented by W1.7.
