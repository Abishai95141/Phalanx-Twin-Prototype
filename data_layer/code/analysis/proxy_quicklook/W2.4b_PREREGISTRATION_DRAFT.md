## 1. Question (AD-33)

Does the identified proxy chain - M07 `separate_fixed` engine, M08 governor with the autothrottle outer loop,
M03 process-disturbance bank (aircraft-common and per-unit factors, the LP shaft-torque path), M12 sensor dynamics
and M13 DASHlink texture - reproduce the behavioural and causal structure of Tail 687's unseen archive-2 flights
as closely as real data reproduces itself across tails (D_tail), and across time (D_temp, strict)?

- The model is driven by each archive-2 flight's recorded inputs only: levers PLA_1-4, ALT, MACH, TAT, PH, the A/T
  engage state and N1 command, and the bleed discretes (BLV, PACK, EAI, WAI/TAI). No output word of an archive-2
  flight (N1, N2, EGT, FF) enters its synthetic version.
- Every model parameter was identified on 687-CAL only (W2.4a-2 stages 1, 4, 5). 652 and 687-TEST were used for
  development (stage 6). Archive 2 is evaluated once.
- Credibility ceiling: NASA-STD-7009B Level 2 against proxy data. A PASS validates the *structure* in proxy mode;
  the proxy is a four-engine regional jet (AD-43), not the F404-IN20.

## 4. Randomness and determinism

- Root seed 20261015. Synthetic flights: `KeyPath(scenario="w24b-gate", tail="T687A2", sortie=<index in the saved
  holdout list> + 1)`; identity-keyed counter streams (AD-37), so each flight's realisation is fixed by its list
  position.
- Bootstrap: `Bootstrap(np.random.SeedSequence(20261015))` (round-2 compatibility mode) with the round-2 request
  order (D_tail, D_temp, then arms in the order PROXY, S_R2b, S_R2a), 2,000 flight resamples.
- Determinism checked before the run: a fresh-process digest of one archive-2-free synthetic flight equals the
  W2.4a A6 digest test (`tests/integration/test_proxy_determinism.py`).

## 5. Battery (primary evidence)

The M20 battery (`phalanx.validation.battery`, the bit-exact port of round 2; README reproduction table): B1-B6
exactly as the round-2 pre-registration section 4 (estimators, bands, airborne rule all four N1 > 25 %), on decoded
engineering values in recorder units (AD-40: units checked, never converted). B7/B8 are not testable on DASHlink.

**Contract-to-battery alignment (AD-40, proposed there and fixed here).** The proxy's synthetic words are produced
at the ACMS sample instants on the replay grid by M13 (`run.simulate_flight` -> `FlightRecord`); the real words are
the MAT 4-Hz grid. Both are on the same sample index grid by construction; no contract round trip is involved in
proxy mode. (If the gate is run through the ground decoder instead, the rule is: latest sample at or before each
grid instant, sentinels kept.)

**Reported alongside (no decision weight):** B1 per phase class (PH 4, 5, 6, taxi) and on the governed segments
(MF1 classes); the A5 behaviours (N1-N2, cross-engine EGT and N2-FF correlations; FF->N2 lag with A/T engaged vs
manual; decel vs accel tau; EGT exponent); MF1 spectral pair decompositions.

## 6. Bars, verdicts, guards and decision

**Bars:** D_tail = holdout (archive 2) vs Tail 652 (equal n); D_temp = holdout early vs late (strict).

| Verdict (per test B1-B6, per arm) | Condition |
|---|---|
| PASS | D_sim <= D_tail |
| FAIL | one-sided 95 % bootstrap lower bound of (D_sim - D_tail) > 0 |
| INCONCLUSIVE | otherwise |
| STRICT PASS (reported) | D_sim <= D_temp |

**Guards.**

| Guard | Rule | Status |
|---|---|---|
| **G0 trivial-cue audit** | pipeline-only metadata subset (round-2 G0 vector, `phalanx.validation.guards.g0`); **one-sided** (AD-40, owner decision 2026-10-14): G0 FAILs only if the 95 % CI **lower** bound of the AUC is above 0.5; a below-chance AUC never FAILs | **Binding** |
| G1 quantiser fidelity | residue-usage histogram distance | Diagnostic |
| Label-leak audit | not applicable (no fault labels in DASHlink) | - |
| Discriminators (D2/D3) | diagnosis only, with family ablation | No verdict |

**Decision (AD-33).**

| Decision | Condition |
|---|---|
| **GATE PASS** | G0 passes; no test FAILs for PROXY; at least 4 of B1-B6 PASS; and PROXY's D_sim is below S_R2b's on at least 4 of the 6 tests (paired, same holdout draws) |
| **GATE PASS WITH FIXES** | G0 passes; one or more FAILs, each attributed to one module (M03/M07/M08/M12/M13) by the stage-6 attribution method, with a fix that changes no module interface or data contract; re-run only on a new pre-registered holdout |
| **GATE FAIL** | G0 fails after pipeline fixes, or PROXY does not beat S_R2b on at least 4 tests, or a FAIL implicates the architecture premise (closed-loop governing + process disturbances cannot reproduce B1/B2) |

The Tejas configuration is declared behaviourally validated in proxy mode only on GATE PASS.
